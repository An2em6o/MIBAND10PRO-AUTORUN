# 自启动模块接入标准

**适用**：任何想"开机自动跑一次"的原生模块（内核模块 / 平台应用），前提是**不改固件、不碰 flash**。

**本文不含任何具体模块的名字** —— 只讲 **为什么这样** 与 **要怎么做**。  
文中每一条规则都有真机事故做依据（末尾 §9 列出）。

**验证环境**：openvela / NuttX 穿戴设备（p67tc，固件 3.101.043）。  
开机链的执行体是一个 **nsh 子集解释器**，不是完整 POSIX shell —— 这一条决定了本文一半的规则。

---

## 0 一句话

> 模块只做一件事：把**开机要跑的那串命令**写进 `/data/rc.d/<你的名字>.sh`，投完就完了。  
> **闸、安全窗口、心跳日志、`/data/rc`、flash —— 一样都不归你。**

---

## 1 谁写什么（边界表）

| 东西                             | 谁负责                                   | 为什么                             |
| ------------------------------ | ------------------------------------- | ------------------------------- |
| `/data/rc.d/<你的名字>.sh`         | **你**                                 | 你的模块开机要干什么，只有你知道                |
| `/data/rc`                     | **管理器**（扫描 `rc.d/` 生成）                | 它是"整条链"的产物，不是任何单个模块的私产          |
| flash 里那句 `sh /data/rc &`      | **管理器**                               | 写 flash **不可逆**；必须只由一处做，且要两段式确认 |
| 防砖闸 `/data/rc.d/.autorun.on`   | **管理器**（建 / 删）＋ **`/data/rc`**（扣 / 放） | 见 §3.1                          |
| 两个安全窗（前 / 后）                   | **管理器**                               | 见 §3.2                          |
| 心跳日志 `/data/rc.d/.autorun.log` | **`/data/rc`**                        | 你的模块对它是**只读**                   |
| 你自己的运行日志                       | **你**（落在你自己的目录）                       | 见 §6                            |
| 命令帧 / 状态回读                     | **你**                                 | 见 §5                            |

**一句话判据**：凡出现第二个模块会跟着一起改的东西 ⇒ 它不该由模块写。

## 2 五个必须（MUST）

### M1 落点与命名

- 放 `/data/rc.d/<名字>.sh`，**一片**（不是你自己的整个脚本目录）。
- 名字只允许 `[A-Za-z0-9_-]`，**小写 + `.sh`**。名字即身份，管理器按文件名排 `order`。
- **为什么**：`/data/rc` 由管理器**生成**。你只能提供"一片"，不能提供"整份" —— 否则两个模块  
  会互相覆盖，而且管理器（和用户）就再也无法回答"到底是谁的行"。

### M2 脚本是**纯命令**：没有 `if`、没有 `sleep`、不碰任何闸

```
set +e
echo start >  /data/<你的目录>/autostart.log
<你的命令…>
echo done  >> /data/<你的目录>/autostart.log
```

- 等待、超时、防砖、恢复策略**全部不在你这里**。
- **为什么**：
  1. 它们是"整条链"的知识，不属于任何单个模块。写进模块里就会出 **N 份互相打架的副本**  
     （老做法：每个模块各带一个安全窗 ⇒ N 个模块白等 N×15 秒；改一处漏一处）。
  2. 更要命的是**可观测性**：老做法下"开机被打断"这件事只在**模块自己的小圈子**里留痕，  
     管理器看不见。真机现象就是——**面板说自启动开着，模块却一条都不跑，日志里一片空白**。

### M3 管理器没装 ⇒ **零写盘**

第一步永远是**试写探针**：

```
试写 /data/rc.d/.probe
  ├─ 成功 → rm -f .probe，继续
  └─ 失败 → 再试写 /data/.probe 来区分两种失败：
              ├─ 能写 /data   ⇒ 报「管理器没装」（告诉用户去装管理器）
              └─ 连 /data 也不行 ⇒ 报「写不进 /data（只读?）」
           两种情况都**立刻返回，一个字节都不写**
```

- **不许自己 `mkdir -p /data/rc.d`**。
- **不许 `exists(目录)` 判"在不在"**：NuttX 上 `open()` 开目录返回 `-6 (ENXIO)`，  
  `io.open(dir)` 给 `nil` ⇒ **目录明明在也会被判成不在**。而 `write_file` 不建父目录，  
  所以"能不能写进去"本来就是你要的那个能力 —— **直接试写最直接**。
- **为什么**：自己建目录 = 宣布"我就是管理器"，装完开机却什么都不发生（**静默失败**），  
  比明确报错危险得多。

### M4 幂等

同样的输入，第二次投递必须**一个字节都不写盘**（内容没变就不写）。

- **为什么**：开机链上的东西没有"重试"概念；能重入才敢让用户随便点。

### M5 不写 `/data/rc`、不碰 flash

- `[删除]` 时**也不要说"我把 `/data/rc` 清理干净了"** —— 你根本不碰它。要如实提示：  
  「注册已撤销；`/data/rc` 里那行是管理器生成的，**去管理器按一次『重建自启动』**&#x5B83;才会消失。」
- **为什么**：不写清这一句，用户会以为"删了但还在跑"，最后得出"这个功能不可信"。

## 3 四个不许（MUST NOT）

### 3.1 不许自带闸

- 不要建 `/data/<你的目录>/autostart.on` 之类的自控开关，也不要在脚本里判它。
- **为什么**：闸**同时**是"用户的总开关"和"整条开机链的防砖凭证"，一把锁**只能有一个主人**。  
  每个模块各带一把 ⇒ N 份互相打架的副本；而且"被打断"只在你自己的小圈子里留痕。
- 管理器生成的 `/data/rc` 长这样（示意，你不用写）：
  ```sh
  set +e
  echo gate_off >> /data/rc.d/.autorun.log    # 心跳，在 if 外面：闸关着也留痕
  if [ -f /data/rc.d/.autorun.on ];then
  rm -f /data/rc.d/.autorun.on                # 先扣闸（防砖凭证）
  sleep 8                                     # 窗口 1
  sh /data/rc.d/<模块A>.sh                    # 各模块串行
  sleep 1                                     # ★ 模块之间固定间隔 1 秒
  sh /data/rc.d/<模块B>.sh
  sleep 15                                    # 窗口 2
  echo cleared >> /data/rc.d/.autorun.log
  echo on > /data/rc.d/.autorun.on            # 跑到底才放行
  fi
  ```
  ⇒ **约 23 秒窗口内**任何一次重启 / 掉电 / 看门狗 ⇒ 闸停在【关】⇒ 下次开机  
  **一条模块命令都不跑、且不自动恢复**（"一次即停"，恢复只能手动）。  
  **你不需要做任何事来配合它** —— 这是设计如此。

### 3.2 不许带 `sleep` / 任何形式的等待

- 你在"窗口 1 之后"才被调起，**该等的已经等过了**。
- 模块之间的**间隔一秒也不用你管**：管理器在两条模块行之间插 `sleep 1`（有几个模块插几次）。
- **为什么**：`/data/rc` 里模块行**没有 `&`** ⇒ 你占的是前台。你多睡一秒，**排在后面的模块  
  就多等一秒**；N 个模块各睡 15 秒 = N×15 秒白等。等待是**链级**参数，只该有一个地方调。

### 3.3 不许用 `&`

- 你的脚本是**被 `sh` 前台串行调用**的。加 `&` 会打乱"跑完一个再跑下一个"的前提。
- **为什么**：串行是**可诊断性**的来源 —— 出问题时能知道"死在谁身上"。并行一旦出事，  
  你连"是不是我"都答不出来。

### 3.4 不许用没有证据的语法

见 §4。

## 4 nsh 语法子集（这是硬约束，不是风格问题）

**已验证可用**：

| 构造                                               | 备注                                    |
| ------------------------------------------------ | ------------------------------------- |
| `set +e`                                         | 第一行固定放它（后面任何命令失败都不要中断整段）              |
| `if [ -f X ];then … fi`                          | 只验过 **`-f`**（文件存在）。**单层**             |
| `rm -f X`                                        |                                       |
| `echo … > X` / `echo … >> X`                     | 追加用 `>>`                              |
| `sleep <秒>`                                      | 秒是整数。**`sleep` 只该出现在管理器那层**（见 3.2）    |
| `insmod <路径> <模块名>`                              | **无引号**形式（真机 rc 里就是它）                 |
| `dd if= of= bs= count= skip= seek= conv=notrunc` | `dd` 是**内建命令**；默认 `bs=0x200`；最多 7 个参数 |
| `ls <目录>`                                        | 只 `ls <目录>`；`ls <单文件>` 会报 stat failed |
| `sh <脚本>`                                        |                                       |

**没有证据（一律不许写）**：`else` · `elif` · `[ ! ]` · `[ -e ]` · `[ -d ]` · `&&` · `||` ·  
`$( … )` · 反引号 · 嵌套 `if` · `for` · `while` · 管道 `|` · `printf` 的 `\x` 转义。

- **为什么**：写错不是"这条不生效"，而是**整段语法错误、开机彻底不跑** ——  
  **比你要修的那个 bug 更糟**。实测过：为了"少写一个 `else`"而绕成单层 `if`，值。
- **行宽**：`nsh_script` 用 `fgets`（256 B 行缓冲）⇒ **每行 ≤ 255 字节**。  
  命令长就把参数写进文件、脚本里只留 `dd`（见 §5.2）。

## 5 三种特殊情况（这是本文的重点）

前两节是"任何模块都照做"。下面是**真机上暴露出来的、必须额外处理的三种情况**。  
按你的模块**逐条自查**。

### 5.1 情况 A：命令**不能**在开机脚本的任务里发

**症状**：同一条命令，**手动按按钮**发没事；**写进开机脚本**就崩（黑屏十几秒 → 重启）。  
重启原因读数往往是 **`rtc_watchdog`（卡死）而不是 fault** —— 说明是"阻塞 / 死等"。

**为什么**：写自建设备节点的处理器**跑在"调用者任务"里**（同步执行）。而开机脚本跑在  
**最低优先级、小栈（8 KB）的任务**里；那条命令真正的动作要进**平台的应用框架**，  
在非 UI 任务里做就会死锁。**命令内容完全无辜，错的是"谁在发"。**

**怎么做**——**延迟命令号（DQ）**：

1. 模块新增一个**独立的命令号** `CMD_xxx_DQ`，语义 = "入环形队列即返回 16"。  
   **原命令号保持全同步**（交互侧常常"写完立刻读状态要求 COMPLETED"，改默认路径会把它打死）。
2. 真正的框架调用交给**模块自己的 UI 线程定时器**派发：一拍一条。
3. 定时器**懒创建**（第一次写时才建）：平台初始化会重置定时器链表，  
   过早创建的定时器会被**静默孤儿化**（不崩、不报错、永不触发）。
4. 定时器句柄只建一次、永不重建；回调里加一条 `timer != 最新句柄 ⇒ return`，  
   防两个活定时器在同一拍连推两阶段（会**静默跳过一步**）。
5. **开机脚本只投"DQ 号"的帧**。

**怎么自证**：

- `.strtab` 里的符号名是**明文** ⇒ 直接对模块字节搜你新写的函数名 / 静态变量名  
  （例：`b'xxx_timer_cb'`、`b'DQ_SEQ'`）就能证明"补丁真的编进了这枚包"，  
  挡的是"改了源码没重编 / 装的是旧包"。**比"源码改了"强得多。**
- 代码里**不许有阻塞等待** —— 但判据要先**剥掉注释**再 grep，否则注释里的 `usleep()` 字样会误报。

### 5.2 情况 B：要发的**不止一条**命令，而且有的命令是"结构性空操作"

**症状**：日志里每条都"成功"、状态字都是 `5`，但设备就是没生效；出事后**没法判凶手**。

**为什么**（两条，都要知道）：

1. **控制层可能直接短路**：有的命令（如"恢复到开机后状态"、"安装 stage 0"）在模块里  
   就是 **`rc = 0`，一行都不跑**。⇒ **`state = 5` 完全不代表它做过任何事。**  
   **唯一可靠的凶手判据是"日志断在哪一行"**，不是任何状态码。
2. **"第 N 条"的口径容易错位**：按脚本里的行号去数，会把"第一条 `dd` 其实是**读状态**"  
   算成命令，整体错一位。**口径只有一个：命令 blob 里的索引（0-based）/ 序号（1-based）。**

**怎么做**：

- 把命令帧做成**一个二进制 blob**（每条固定 16 B：`magic | cmd | arg0 | arg1`），  
  安装时一次写盘；脚本里**平铺展开**逐条 `dd`（**不要 for 循环** —— nsh 没有）：


  ```sh
  dd if=/data/<你的目录>/cmds.bin of=<设备节点> bs=16 skip=0 count=1 conv=notrunc
  dd if=/data/<你的目录>/cmds.bin of=<设备节点> bs=16 skip=1 count=1 conv=notrunc
  …（有几条写几条）
  ```
- 两个魔数挑成**可打印 ASCII** ⇒ 字节流肉眼可核（例：能核出 `"1ABC1XYZ"` 这种串）。
- **每条动作前后各一条埋点**（见 §6），并让"第 N 条"用 **blob 索引**编号。
- **进框架的那几条必须是 DQ 号**（情况 A）；**结构性空操作的那几条原样保留**（它们无害，  
  而且改了反而与交互侧不一致）。

**怎么自证**：离线门里

- 独立复算每条帧的 `magic` + 命令号 + `arg0`（**别引用被测代码的常量表**，否则等于自己证自己）；
- 写一条**回放判据**：把脚本回放到"第 N 条 `dd` 之前"就停，断言日志尾行**正好**是第 N 条的前置埋点。  
  这条能把"埋点写错位置"钉死 —— 否则上机才发现。

### 5.3 情况 C：**运行依赖**（模块本体）开机时不在固定路径

**症状**：`insmod` 报找不到文件；或者"每次都装成功、开机就是不生效"。

**为什么**：模块本体是**随安装目录落的**（平台把每个安装包解到一串随机/带 hash 的路径下）。  
开机那一刻，**那个随机路径已经不存在了**。

**怎么做**：

- 安装时把本体**复制到一个固定名**：`/data/<你的目录>/<模块名>.bin`，  
  并**回读校验逐字节相同**（复制也要有判据）。
- 脚本里 `insmod` 那个**固定名**。
- 顺带把**其它开机要读的东西**（命令 blob、图标等）也放到固定目录，  
  让脚本只引用固定路径 —— **脚本里不许出现"随安装而变"的路径**。

**怎么自证**：安装后回读固定名文件 == 包内那份（逐字节）。

## 6 可观测性：埋点 + 两处日志

**你只有一个武器：日志。** 因为硬重启时 console 拿不到现场。

### 6.1 埋点铁律：只写"前瞻标记"，绝不写"事后结论"

```sh
echo p3 >> LOG                 # ← 动作**之前**：若日志到此为止，凶手就是第 3 条
dd if=... skip=3 count=1 conv=notrunc of=...
echo q3 >> LOG                 # ← 动作**之后**
```

- **反面教材**（曾把人带偏两轮）：在动作后面无条件写一句"崩了 ⇒ 凶手就是第 N 条"  
  ⇒ 每一步都会印一句"凶手就是第 N 条"。
- **判读口诀**：上一行是 `qN` ⇒ 崩在紧跟的回读 / 后续动作里；上一行是 `pN` ⇒ 崩在**这一次写**里。

### 6.2 两处日志，分工不同，别只看一个

| 文件                           | 谁写                           | 末行含义                                                      |
| ---------------------------- | ---------------------------- | --------------------------------------------------------- |
| `/data/<你的目录>/autostart.log` | **你的脚本**                     | `done` = **本模块**跑到底；停在 `start` / `insmod` / `m1`… ⇒ 卡在哪一步 |
| `/data/rc.d/.autorun.log`    | **管理器的 `/data/rc`**（你**只读**） | `cleared` = **整条链**跑到底；末行 `gate_off` = 闸此刻是【关】（上次被打断过）    |

- **为什么必须两个**：你的日志管"我内部走到哪"，链日志管"整条链跑完没有"。  
  只看前者会把"**闸关着、整条链根本没跑**"误判成"我的脚本没写对"。

### 6.3 别在日志里写"结论"，写"事实"

写 `echo m3 >> LOG`，不要写 `echo "好" >> LOG`。  
写**人可读的短词**上屏，把**完整理由 `print()` 进设备日志**（屏上一行放不下会被裁切）。

## 7 安装 / 删除：三个容易漏的动作

| 动作                                         | 为什么                                 |
| ------------------------------------------ | ----------------------------------- |
| `[安装]` 前先 §M3 试写探针                         | 管理器没装就该**零写盘**+明确报错                 |
| `[安装]` 和 `[删除]` 都要 `rm -f` 掉**旧版的"模块自带闸"** | 它是死文件；留着会让后来的人（和你自己）以为"模块还有闸"，把排查带偏 |
| 只摘**完全等于**你自己旧版那一行，别人的行**一字不动**            | 不变量：管理器**永远**不替你删不认识的行 —— 你也不该删别人的  |
| `[删除]` 后提示用户"去管理器按一次『重建自启动』"               | `/data/rc` 是管理器生成的，你撤不掉那一行          |

**旧版"整份覆盖"式实现的坑**：如果某个旧版是**整体覆盖**写 `/data/rc`（而不是追加一行），  
那"只摘完全相等的那一行"的判据**匹配不上 ⇒ 摘不掉**。要在文档里写明这条，  
别变成"看起来清理了、其实没清"（残留会让模块**开机跑两遍**）。

## 8 交付前的自证清单

**离线门**（强烈建议这么做，能挡掉绝大多数低级错）：

- 用**真解释器**跑真源码（语言层面的东西不要用别的语言重写一遍 —— 那测的是重写，不是你的代码）。
- 假的：UI 库 / 文件系统 / 执行器 / 设备节点。
  - ★ 假文件系统**必须遵守"父目录不在 ⇒ 打不开"** —— 这正是"依赖的那个 App 没装"能被判出来的机制；  
    若无条件成功，"零写盘"这条判据就是**假通过**。
  - ★ 假设备节点要**真的按包更新状态字**，否则"写完回读校验"全是假判据。
- **nsh 回放器**：脚本**不要**用被测语言跑，写一个**小的 Python 子集解释器**，  
  **只实现脚本真正用到的构造，遇到未建模的构造直接 `AssertionError`** ——  
  这样"脚本里混进了设备上不存在的语法"会**立刻暴露**，而不是被静默跳过。
- **反向判据一律先剥注释**：判"代码里不许出现 X"时，不剥注释会把"解释为什么不用 X"的头部注释  
  误咬，逼人删掉有用的说明。
- ★★ **判据要翻面，不要只删不放**：从"必须有闸判句 / 必须有 sleep"改成"不许有"时，  
  **必须同时把新判据加上**。只放宽不放紧 = 没有判据。

**静态自证（对着交付物验，不是对着源码）**：

- [ ] `/data/rc.d/<名字>.sh` 存在，末行以换行结尾
- [ ] 首行 `set +e`；**全文无 `if` / `fi` / `sleep` / 任何闸文件名**
- [ ] 一行都不带 `&`
- [ ] 每行 ≤ 255 字节；命令白名单全在 §4 表里
- [ ] 脚本里**没有** `/data/rc`、没有 flash 设备路径、没有"随安装而变"的路径
- [ ] 代码（剥注释后）没有：写 `/data/rc`、写 flash、建闸、`AS_*DELAY` 之类常量
- [ ] 幂等：再投一次，盘上字节不变
- [ ] `[删除]` 后：脚本没了、旧版闸没了、`/data/rc` **没被动过**、运行依赖**没被删**
- [ ] 如果打包：**包内那份 == 你验过的那份**（改源码忘了重新打包，是这条链上唯一会静默出错的环节）

## 9 常见驳回原因（每一条都对应一次真机事故）

| #  | 驳回                                | 为什么                                                                                        |
| -- | --------------------------------- | ------------------------------------------------------------------------------------------ |
| 1  | "我给模块加了个开关文件"                     | 闸只能有一个主人（§3.1）                                                                             |
| 2  | "我 `sleep 15` 等它起来"               | 等待是链级参数；你多睡，后面所有模块跟着等（§3.2）                                                                |
| 3  | "我手动跑没问题啊"                        | 手动 = 应用任务；开机 = 最低优先级小栈任务。**换的是任务，不是命令**（§5.1）                                              |
| 4  | "日志里每条都 state=5，都成功了"             | 有的命令在控制层就短路成 `rc=0`，一行都不跑（§5.2）                                                            |
| 5  | "我把 `/data/rc` 覆盖成我自己的了"          | 它是管理器生成的产物，别人还有行在里面                                                                        |
| 6  | "我 `mkdir -p /data/rc.d` 了，免得没目录" | 等于宣布自己是管理器；管理器没装时变成**静默失败**（§M3）                                                           |
| 7  | "我判了 `exists(目录)`"                | NuttX 上开目录返回 `-6`，`io.open` 给 `nil` ⇒ 假阴性（§M3）                                             |
| 8  | "我用了 `&&` / `else` / 嵌套 `if`"     | 没证据 ⇒ 整段语法错误、开机彻底不跑（§4）                                                                    |
| 9  | "我加了个 `for` 循环少写几行"               | nsh 没有 `for`（§4）                                                                           |
| 10 | "我把 `sleep` 放进模块（免得脚本等）"          | 模块里**唯一**的时间源是 UI 定时器 ⇒ 息屏就停；而且模块通常**不允许**调用阻塞等待。**与屏幕无关的延时只有脚本侧做得到** —— 而现在连脚本侧也不该做（§3.2） |

## 10 两个样本骨架（照抄即可）

### 样本一：只要发**一条**命令

```sh
set +e
echo start > /data/<D>/autostart.log
insmod /data/<D>/<模块名>.bin <模块名>
echo insmod >> /data/<D>/autostart.log
echo m1 >> /data/<D>/autostart.log
dd if=<设备节点> of=/data/<D>/status1.bin bs=384 count=1 conv=notrunc
echo m2 >> /data/<D>/autostart.log
dd if=/data/<D>/boot.bin of=<设备节点> bs=16 count=1 conv=notrunc
echo c0 >> /data/<D>/autostart.log
dd if=<设备节点> of=/data/<D>/status2.bin bs=384 count=1 conv=notrunc
echo m3 >> /data/<D>/autostart.log
echo done >> /data/<D>/autostart.log
```

### 样本二：要发**多条**命令 + 多次回读
```sh
set +e
echo start > /data/<D>/autostart.log
insmod /data/<D>/<模块名>.bin <模块名>
echo insmod >> /data/<D>/autostart.log
echo m1 >> /data/<D>/autostart.log
dd if=<设备节点> of=/data/<D>/status1.bin bs=384 count=1 conv=notrunc
echo m2 >> /data/<D>/autostart.log
dd if=/data/<D>/cmds.bin of=<设备节点> bs=16 skip=0 count=1 conv=notrunc
echo c0 >> /data/<D>/autostart.log
dd if=/data/<D>/cmds.bin of=<设备节点> bs=16 skip=1 count=1 conv=notrunc
echo c1 >> /data/<D>/autostart.log
…（有几条帧写几条，skip 递增）
echo m3 >> /data/<D>/autostart.log
dd if=<设备节点> of=/data/<D>/status2.bin bs=384 count=1 conv=notrunc
echo m4 >> /data/<D>/autostart.log
dd if=<设备节点> of=/data/<D>/status3.bin bs=384 count=1 conv=notrunc
echo m5 >> /data/<D>/autostart.log
ls /data/<D> >> /data/<D>/autostart.log
echo done >> /data/<D>/autostart.log
```

**两份的共同点就是标准本身**：纯命令 · 无 `if` · 无 `sleep` · 无 `&` · 不碰闸 ·
不碰 `/data/rc` · 不碰 flash · 每条动作前后留痕 · 痕迹全落在**自己的目录**。
差别只在"要发几条、回读几次"—— 那是你模块自己的事。

## 附：一页速查

```
落点       /data/rc.d/<名字>.sh       （小写，[A-Za-z0-9_-]）
首行       set +e
内容       纯命令；无 if / 无 sleep / 无闸 / 无 & / 每行 ≤ 255 B
前置       试写 /data/rc.d/.probe 失败 ⇒ 报「管理器没装」+ 零写盘
幂等       内容没变不写盘
不许       写 /data/rc · 碰 flash · 建自己的闸 · 用没证据的语法
必做       安装/删除 rm -f 旧版模块闸 · 删除后提示「去管理器重建」
命令       >1 条 ⇒ 做成 blob，脚本逐条 dd skip=N 平铺；进框架的那几条用 DQ 号
依赖       模块本体复制到固定名（开机时随机安装目录已不存在）
日志       自己目录一份（模块内部走到哪）；/data/rc.d/.autorun.log 只读（整条链）
等待       不用管：管理器给「前窗口 8 s + 后窗口 15 s」，模块之间插 sleep 1
防砖       不用管：约 23 s 窗口内被打断 ⇒ 闸停在关 ⇒ 下次全不跑，只能手动恢复
```
