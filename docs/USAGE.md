# 使用教程 —— 让模块每次开机自动跑一次

> **这篇是写给普通用户的。** 不需要会编程，不需要开电脑，全程在手表上手点。  
> 跟着做一遍就会了，全篇以 **Chaos 模块**为例。
>
> 技术细节（设计原理、判据、接入标准）在 [`README.md`](../README.md) 与  
> [`MODULE-STANDARD.md`](../MODULE-STANDARD.md)，这篇**不讲那些**。

---

## 0. 先用一分钟看懂"为什么要有两个东西"

你可能会问：**装一个模块，为什么要装两个 App？**

因为"模块"和"让模块开机自动跑"是**两件不同的事**，由两个不同的东西负责：

|                        | 干什么                                                | 打个比方      |
| ---------------------- | -------------------------------------------------- | --------- |
| **10pro.autorun**（管理器） | 管"**什么时候跑**"：开机那一刻，按顺序把各模块叫起来；谁被禁用了就不叫；上次没跑完就停下来报警 | 小区的**物业** |
| **模块自己**（如 Chaos）      | 管"**跑起来干什么**"：装模块、注册应用、换字体……                       | 你家**入户**  |

**关键规矩（记住这一条，后面全通）**：

> **模块只管"自己要干什么"，把一张写着"开机要跑什么"的小纸条交到物业手里；  
> 至于几点开门、要不要等电梯、谁排前面，全归物业。**

所以：

- **模块不能自己开开关** —— 开关只有物业有（就是管理器 `[3 开启]` / `[4 关闭]`）。
- **模块不能自己加延时** —— 什么时候跑由物业排。
- 你**禁用**某个模块，是跟物业说"别叫它"；模块本身**一个字节都没动**，随时能开回来。

## 1. 装之前：先确认这三件事

| 项目   | 要求                                              | 在哪看         |
| ---- | ----------------------------------------------- | ----------- |
| 机型   | **小米手环 10 Pro**（`miwear.watch.p67tc` / M2553B1） | 手环「设置 → 关于」 |
| 固件版本 | **v3.101.043**                                  | 同上          |
| 所需文件 | 见下面清单                                           | 从发布页下载      |

**要准备的文件（就两个，别多也不会少）**：

| 文件                   | 干什么用                          | 什么时候装          |
| -------------------- | ----------------------------- | -------------- |
| `10pro.autorun.face` | **管理器** —— 管自启动的              | **第一个装，必须先装它** |
| `chaos_inst.face`    | **Chaos 模块安装器** —— 装 Chaos 用的 | 第二个装           |

> ### ⛔ 顺序不能反：**先管理器，后模块**
>
> 新模块 + 旧管理器（或没有管理器）= **防砖能力为零**。  
> 意思是一旦模块在开机时卡住，下次开机还卡在同一处，**手环会开不了机**。  
> 管理器在的话，这种情况它会把开关扣住、让后面不跑，你手动开一次就能恢复。
>
> **所以：先装管理器，再装模块。** 这是全篇最重要的一句话。

> ### ⚠️ 风险告知（自己判断）
>
> 这套东西走的是**固件注册链**，属于非授权修改。有可能**失去保修、变砖、或随固件升级失效**。  
> 只在你**自己拥有**的设备上弄。固件不是 v3.101.043 的**不要照做**。

## 2. 第一步：装管理器（"物业"开张）

### 2.1 把管理器装进手环

跟装普通第三方表盘**完全一样**：

1. 把 `10pro.autorun.face` 传到手机上；
2. 用官方的**表盘安装/侧载**通道把它装进去；
3. 装完，表盘的列表里会出现一枚 **`10pro.autorun`**。

### 2.2 打开它，装开机钩子

在表盘列表里切到 `10pro.autorun`，你会看到主页：

```
        10pro.autorun
       多模块开机自启管理
   rc 可读 生成0 别人0 自启开
 ┌────────────┬────────────┐
 │ 1 自启动管理 │ 2 重建自启动 │
 ├────────────┼────────────┤
 │ 3 模块管理  │  4 日志     │
 └────────────┴────────────┘
   （下面是日志小窗）
```

**操作**：

| 第几步 | 按哪里                | 会看到什么      |
| --- | ------------------ | ---------- |
| ①   | 主页 **`1 自启动管理`**   | 切到"自启动"页   |
| ②   | 自启动页 **`1 安装`**    | 日志小窗说话（见下） |
| ③   | **可能要再按一次 `1 安装`** | 第二次才真正写进去  |

### 2.3 ★ 为什么"可能要按两次" —— 不是坏了

这是**故意**的，因为第二步会写 flash（不可逆），必须让你确认一次：

**第一下 `1 安装`** —— 只**探测**，不写任何东西：

```
init rc 探测: <探测结果>
认出 <分区名> (原样) -> 再按一次 [1 安装] 才写 flash
```

→ **再按一次 `1 安装`**，这次才真装：

```
init rc: 装好 (...)
目录/配置: /data/rc.d + autorun.json 就位
总开关: 已打开 (...)
已重建 /data/rc: 0 行生成 + 0 行别人的
```

> **例外**：如果你（或之前的人）已经装过了，第一下就会认出"已经是载荷了"，  
> 直接说 `不用再按 (已是载荷)` 并一次做完 —— 这时**按一下就够**。

### 2.4 装好了怎么确认

看自启动页那几行状态（**这页是你以后最常来的地方**）：

| 那行    | 应该显示                     | 白话                    |
| ----- | ------------------------ | --------------------- |
| `开关:` | `总开关 开 -> 已启动`           | 总闸开着 ✅                |
| `心跳:` | `没有记录 (还没开过机)`           | 还没重启过，正常（重启后会变成"跑到底"） |
| `安装:` | **`init rc 已装 (<分区名>)`** | ★ **这句才是"装好了"**       |
| `模块:` | `装了 0 个, 会跑 0 个`         | 还没装模块，正常              |
| `rc:` | `生成 0 行, 别人的 0 行`        | 还没模块行，正常              |

> **★ 认准 `安装: init rc 已装`。** 只要这句在，开机钩子就装好了。  
> 如果它还写着 `未装, 分区原样 … 按 [1 安装]`，就是还没装上，回去按 `1 安装`。

**到这一步，"物业"就上班了。** 但现在还没有任何模块，所以开不开机都一样。

## 3. 第二步：装 Chaos 模块

现在装模块本体。它和刚才的管理器**没关系**，是两个独立的包。

### 3.1 把安装器装进去

1. 把 `chaos_inst.face` 传到手机，用**同一条表盘侧载通道**装进去；
2. 表盘列表里切到它，显示名是 **`Chaos 自启动`**；
3. 界面出现：标题 `Chaos 安装器` + 一张状态卡（写着 `准备就绪`）+ 三个按钮。

### 3.2 点 `运行`，走完 11 步

| 第几步 | 按哪里      | 会看到什么                                                                                            |
| --- | -------- | ------------------------------------------------------------------------------------------------ |
| ①   | **`运行`** | 状态卡变成"正在运行"，然后**一步一步往下走**                                                                        |
| ②   | 等        | 界面会**逐步刷新**，共 11 步：部署模块 → 部署图标 →（字体槽跳过）→ 加载模块 → 检查设备 → 设置语言 → 恢复占位 → 注册应用 → 通知系统 → 发布应用 → 发布桌面条目 |
| ③   | 等它结束     | 桌面上**多出一枚 Chaos 图标**，点进去就是 Chaos 自己的界面                                                           |



> ### ⚠️ 三个必须知道的点
>
> 1. **走完 11 步之前不要关掉这个界面**，让它自己跑完。
> 2. **桌面上出现图标 ≠ 模块已经装完**，要等 11 步全走完。
> 3. **第二次点 `运行` 会失败，并让你"先关机再开机"** —— 这是**故意的**，不是 bug。  
>    这个模块设计上从不"卸载后重装"（会导致开机崩溃），所以每次开机**只能运行一次**。  
>    想重新跑，重启手环之后再点。



> **装完可以不管了。** 到这里 Chaos 已经能用了 —— 桌面图标能点、功能都在。  
> **但它还不会开机自动跑**，因为"小纸条"还没交给物业。这是下一节。

## 4. 第三步：让 Chaos 开机自动跑（★ 核心）

这一步是把模块的"小纸条"交给管理器。**就在 Chaos 安装器里按一下**。

### 4.1 在 Chaos 安装器里"投小纸条"

| 第几步 | 按哪里            | 会看到什么                                   |
| --- | -------------- | --------------------------------------- |
| ①   | 主视图点 **`自启动`** | 切到自启动页：标题 `自启动` + 一行状态 + **两个按钮**       |
| ②   | 按 **`安装`**     | 提示变成：**`已投 rc.d/chaos.sh → 管理器按[1]`** ✅ |

**这一页只有两个按钮，很简单：**

| 按钮     | 作用                                     |
| ------ | -------------------------------------- |
| `安装`   | 把 Chaos 的"开机要跑什么"交给管理器（**一按即装**，不是两段式） |
| `删除`   | 撤回（提示：`已撤销 → 管理器按[1] 清 rc 那行`）         |
| `< 返回` | 回主视图                                   |

> **★ 这一页没有"开/关自启动"按钮 —— 这是故意的。**  
> 要不要跑，**整个归管理器**（管理器的 `[3 开启]` / `[4 关闭]`，以及模块列表里的"允许/禁止"）。  
> 模块这边再放一个开关，就会出现"两个地方说法不一样"，谁也说不清到底跑不跑。

> **可能遇到的报错（照做就行）**：
>
> - 提示 **`管理器没装: 无 /data/rc.d`** ⇒ 你还没装管理器，或者没点过它的 `[1 安装]`。**回去做第 2 节。**
> - 提示 **`写不进 /data (只读?)`** ⇒ 这是设备/挂载的问题，不是操作问题。
>
> 这两种情况它**一个字节都不会写**，所以放心按。

### 4.2 ★ 回管理器，按 `2 重建自启动`

**这一步不能省！** 模块只是把纸条交给了物业，物业**还没把它排进值班表**。

| 第几步 | 按哪里                        | 会看到什么                                    |
| --- | -------------------------- | ---------------------------------------- |
| ①   | 表盘列表切回 **`10pro.autorun`** | 打开管理器主页                                  |
| ②   | 按主页 **`2 重建自启动`**          | 日志里出现：**`已重建 /data/rc: 1 行生成 + 0 行别人的`** |

**怎么知道成功了？** 从 `1 行生成` 就看出来了 —— 之前是 `0 行生成`，现在变成 1，说明 Chaos 那行**排进去了**。

也可以从主页状态行看：`rc 可读 生成1 别人0 自启开`。

### 4.3 重启手环，验证

| 第几步 | 动作                                 | 期望                  |
| --- | ---------------------------------- | ------------------- |
| ①   | 重启手环                               | —                   |
| ②   | 起来后，切到 `10pro.autorun` → `1 自启动管理` | 看那两行（见下）            |
| ③   | 或者看 Chaos 那边                       | 桌面图标能点、功能正常 = 它跑起来了 |

**管理器自启动页应该变成：**

```
开关: 总开关 开 -> 已启动
心跳: 上次开机 跑到底          ← ★ 看到"跑到底"就是成功
安装: init rc 已装 (...)
模块: 装了 1 个, 会跑 1 个
rc:   生成 1 行, 别人的 0 行
```

> ### ⏱️ 别在开机后 23 秒内重启！
>
> 开机那 23 秒是"防砖窗口"。**在这个窗口里重启/掉电，自启动会被自动扣住**，  
> 之后每次开机都不跑，要你手动开一次。这是**故意的保护**，不是故障。
>
> 开机后如果马上看面板写着「未启动」，**先等半分钟再看**。  
> 详见 [第 8 节 出了问题怎么办](#8-出了问题怎么办).

**🎉 到这里，Chaos 已经开机自动跑了。**

## 5. 日常管理：模块管理页

过了上面三步，日常你只需要一个页面：**主页 `3 模块管理`**。

### 5.1 这页长什么样

```
        < 返回        模块管理 2
 ┌────────────────────────────────┐
 │ chaos                          │
 │ order 10 · ...        允许     │  ← 点一下 = 允许 ⇄ 禁止
 ├────────────────────────────────┤
 │ shellpp2                       │
 │ order 20 · ...        允许     │
 └────────────────────────────────┘
 ┌────────┬────────┬────────┐
 │全部启用 │  重建  │全部禁止 │
 └────────┴────────┴────────┘
```

- 标题上的 **`模块管理 N`** 就是**一共装了 N 个模块**。
- 列表可以**上下滑动**（一屏看得见 6 个）。
- 每行右边的状态词，一共四种：

| 状态词     | 颜色 | 什么意思                                          |
| ------- | -- | --------------------------------------------- |
| **允许**  | 绿  | 开机**会**跑它 ✅                                   |
| **禁止**  | 红  | 开机**不跑**它（模块本身没动，随时能开回来）                      |
| **核心**  | 灰  | 系统核心模块，**不给禁**（要停得用它自己的开关）                    |
| **缺脚本** | 灰  | `/data/rc` 里还留着它的行，但脚本已经没了 → **按一次 `重建` 就消失** |

### 5.2 三件事，很简单

| 想干什么          | 怎么做                                     |
| ------------- | --------------------------------------- |
| **不让某个模块开机跑** | 点那一行 → 状态变 **`禁止`** → 再按 **`重建`**       |
| **让它重新跑**     | 点那一行 → 状态变 **`允许`** → 再按 **`重建`**       |
| **一次全开 / 全禁** | 按 **`全部启用`** / **`全部禁止`** → 再按 **`重建`** |

> ### ★ 改完一定要按 `重建`
>
> 点行、点"全部启用/禁止"，**都只是改了配置，还没生效**。  
> 管理器会在日志里明确提醒你：`-> 配置已改, 按 [2 重建自启动] 才落到 /data/rc`。  
> 「重建」这个键**每个页面都有**：
>
> - 模块管理页 → **`重建`**
> - 主页 → **`2 重建自启动`**
>
> 按哪个都一样。**不按 = 改了等于没改。**

### 5.3 总开关（一次管所有）

管理器的自启动页上有两个键，管的是**所有模块**：

| 键          | 作用                     | 什么时候用                    |
| ---------- | ---------------------- | ------------------------ |
| **`3 开启`** | 总闸开 → 开机会跑所有"允许"的模块    | 平时保持这个状态；**被打断后也是按这个恢复** |
| **`4 关闭`** | 总闸关 → **开机会一条模块命令都不跑** | 想临时全停（比如设备不正常时排查）        |

> **`4 关闭` 和逐个"禁止"的区别**：
>
> - **`4 关闭`** = 总闸，**所有**模块一起停，改的时候**一个模块的策略都没动**，开回来立刻恢复原样。
> - **逐个"禁止"** = 只停那一个，其他照跑。
>
> **`4 关闭` 之后一定要按 `重建`**，否则会看到面板提示 **`●待重建`**（= 改了还没落盘）。

## 6. 重建：什么时候必须按

「重建」= 让管理器**重新生成开机值班表**。管理器不会自己偷偷重建（这是刻意的 ——  
不然"打开一下 App"就悄悄改了开机脚本，而你是看不见的）。

**必须按「重建」的四种情况**：

| # | 你做了什么                          | 必须按重建                | 不按会怎样                       |
| - | ------------------------------ | -------------------- | --------------------------- |
| 1 | **装了一个新模块**，并在它里面点了 `安装`（投了纸条） | ✅                    | 模块装了但**开机不跑**               |
| 2 | **卸载/删除了一个模块**                 | ✅                    | 值班表还留着那行，**开机去跑一个已经不存在的文件** |
| 3 | 在模块管理页改了 **允许/禁止**             | ✅                    | 改了等于没改                      |
| 4 | 按了总开关 **`3 开启` / `4 关闭`**      | ✅（`开启`会自动重建，`关闭`要手动） | 面板显示 `●待重建`，改动不生效           |

**按哪个键都行**：主页 `2 重建自启动`，或模块管理页的 `重建`。  
（另外，自启动页的 `1 安装` 和 `3 开启` 也会顺带重建一次。）

### 6.1 「重建」说了什么

| 日志里出现                          | 意思             | 要做什么                          |
| ------------------------------ | -------------- | ----------------------------- |
| `已重建 /data/rc: N 行生成 + M 行别人的` | ✅ 成功           | 重启生效                          |
| `重建: 内容未变, 未写盘`                | ✅ 成功，只是没必要改    | 不用管                           |
| `拒绝重建: ... 建不出来`               | ❌ 配置坏了         | 去自启动页按 `1 安装` 重建目录/配置         |
| `拒绝重建: /data/rc 读不出来`          | ❌ 读不到的**别人的行** | **不能重建**（重建会把别人的行抹掉，所以管理器拒绝动） |

> ### 什么是"别人的行"？
>
> `/data/rc` 里除了管理器生成的行，可能还有**别的系统或工具**放的行。  
> 管理器的铁律是：**别人的行一个字都不动**。所以重建只重写自己那部分。  
> 上面第 4 种"拒绝"就是在保护这个 —— **读不出来就不敢动，宁可不动**。

## 7. 卸载：怎么退回去

★ 注意顺序：**先撤模块，后卸载管理器**。反过来会让某个模块的开机行成为"孤儿"。

| 想干什么                   | 在哪按                                                | 会不会删我的东西                         |
| ---------------------- | -------------------------------------------------- | -------------------------------- |
| **只让某个模块不再开机跑**（推荐，最轻） | 模块管理页点它 → `禁止` → `重建`                              | 模块本身**一个字都没动**                   |
| **撤销模块的自启动登记**         | Chaos 安装器 → `自启动` → **`删除`** → 回管理器按 `重建`          | 只删纸条，模块本体还在                      |
| **删除模块本体及全部数据**        | Chaos 安装器 → **`清除重置`**（**要按两次**，第一下提示 `再按一次以确认清除`） | ⚠️ 连数据一起删，要重启后重新 `运行`            |
| **整体停用自启动**（保留所有配置）    | 管理器 → `1 自启动管理` → **`4 关闭`** → 按 `重建`              | 配置、模块脚本、`/data/rc` **全保留**，随时开回来 |
| **彻底摘掉开机钩子**           | 管理器 → `1 自启动管理` → **`2 卸载`**                       | ⚠️ 见下                            |

### 7.1 `2 卸载` 到底删了什么（★ 容易误会）

**`2 卸载` 只做两件事**：还原 flash 里的开机钩子 + 删总开关。

**它明确保留：**

```
保留: autorun.json / /data/rc / 各模块脚本 (一个字节都没动)
-> 下次开机不会再跑 /data/rc
```

也就是说：

- ✅ 你的**模块还在**、模块数据还在、桌面图标还能点；
- ✅ 你配的**允许/禁止**记录还在；
- ✅ **`/data/rc` 还在**（只是开机会不执行它）；
- ❌ 只是**开机会不跑它**了。

**所以想回来的话**：自启动页按 `1 安装` 就能原样接回去，**不用重新配一遍**。

> **和 `清除重置` 的区别**：
>
> - 管理器的 `2 卸载` —— 拆"物业"，不动任何模块。
> - Chaos 的 `清除重置` —— 拆模块本身，连数据一起删。  
>   两个是**独立的**，可以只拆一个。

> **`2 卸载` 也是两段式的**：第一下只探测（`再按一次 [2 卸载] 才还原`），第二下才动手。  
> 如果 flash 本来就是原样，第一下就直说 `不用再按 (无需还原)` 并做完。

## 8. 出了问题怎么办

### 8.1 ★ 先看两行，别急着翻文件

**切到 `10pro.autorun` → `1 自启动管理`，只看最上面两行。**

**第一行 `开关:`**

| 显示                    | 意思                         |
| --------------------- | -------------------------- |
| `总开关 开 -> 已启动`        | ✅ 自启动是开的                   |
| `总开关 关 -> 未启动, 按[3]开` | ❌ **闸是关的** → 按 `3 开启`，然后重启 |

**第二行 `心跳:`**

| 显示                  | 意思                                        |
| ------------------- | ----------------------------------------- |
| `上次开机 跑到底`          | ✅ 上次正常跑完了                                 |
| `上次开机 没跑到底 -> 闸被扣住` | ⚠️ **上次开机被打断了**（重启/掉电/看门狗）→ 按 `3 开启`，然后重启 |
| `没有记录 (还没开过机)`      | 还没重启过，正常                                  |

### 8.2 症状 → 怎么办（照着查）

| 症状                   | 最可能的原因              | 怎么办              |
| -------------------- | ------------------- | ---------------- |
| 面板显示「**未启动**」        | 闸是关的                | 按 `3 开启` → 重启    |
| 心跳写「**没跑到底 → 闸被扣住**」 | **上次开机被打断了**（防砖生效了） | 按 `3 开启` → 重启    |
| 面板**全正常**，但模块就是没动静   | `/data/rc` 里没有它那行   | 按 `2 重建自启动` → 重启 |
| 面板显示 **`●待重建`**      | 改了开关但没落盘            | 按 `2 重建自启动`      |
| 模块页出现「**缺脚本**」       | 模块被删了，但值班表还留着那行     | 按一次 `重建`，那行会自己消失 |
| 上面全正常、重启后还是不跑        | 那才轮到模块自己的问题         | 不归管理器管，见模块自己的文档  |

### 8.3 ★★ 最重要的一条：别在开机后 23 秒内重启

开机时，管理器会**先扣住闸**，跑完所有模块、再等一会儿**才放开** —— 整个过程约 **23 秒**。

**在这个窗口里重启 / 掉电 / 看门狗**，闸就停在【关】。  
之后**每次开机一条模块命令都不跑，而且不会自动恢复**（这是刻意的，为的是不让手环陷入"开机→崩→重启→又崩"的死循环）。

**恢复方式只有一个：手动按 `3 开启`（或 `1 安装`），然后重启。**

> **换句话说**：你如果看到"自启动又没生效"，先想想**是不是刚开机就重启过**。  
> 十有八九是这个原因，不是坏了。

### 8.4 搞清楚"是谁的问题"：两处记录各判一半

不用连电脑，只看**面板给人的信息**就够了 —— 管理器记的和模块记的，管的是两件不同的事：

| 看哪 | 谁写的 | 告诉你什么 |
|---|---|---|
| 管理器 → `1 自启动管理` 的**心跳行** | **管理器**（开机值班表） | 「跑到底」= 整条链跑完了；「没跑到底 → 闸被扣住」= 上次被打断了 |
| 模块自己的日志 / 界面状态 | **模块自己** | 它自己走到哪一步了 |

> **为什么两处都要看**：只盯模块那边，会把"**闸关着、整条链根本没跑**"误判成"模块坏了"。
> **先看管理器那两行**（[8.1](#81--先看两行别急着翻文件)），再去看模块。

## 9. 常见问题（FAQ）

**Q：我装了模块、也点了 `安装`，为什么开机还是不跑？**  
A：90% 是**忘了按 `重建`**。模块只交了纸条，管理器还没排值班表。  
回管理器按 `2 重建自启动`，看日志出现 `已重建 /data/rc: N 行生成` 就成了。

**Q：我按了 `4 关闭` 让模块全停，现在开不回来了？**  
A：按 `3 开启`，**再按一次 `重建`**，然后重启。你逐个配的允许/禁止一个都没丢。

**Q：模块管理页里出现「缺脚本」，点它没反应？**  
A：对的，"缺脚本"的行点了本来就没用（模块文件都没了）。**按一次 `重建`，那行会自己消失**。

**Q：我能在管理器里禁用一个模块吗？它会不会被删掉？**  
A：禁用它**只是不叫它**，模块**一个字节都没动**。桌面图标还在、点开还能用。想跑回来点成"允许"再 `重建` 就行。

**Q：总开关关着的时候，桌面上的 Chaos 图标还能点吗？**  
A：能。总开关只管**开机要不要自动跑一次**，跟"平时能不能用"完全无关。

**Q：为什么"第二次点 `运行` 会失败"？**  
A：故意的。那个模块设计上从不做"卸载后重装"（会让开机崩溃），所以每次开机只能 `运行` 一次。  
想再跑，**重启手环**之后再点。

**Q：为什么 Chaos 的"自启动"页上找不到"开自启动"？**  
A：因为**开关在管理器那边**。Chaos 那页只有 `安装`（交纸条）/ `删除`（撤纸条）。  
要开/关，去管理器的 `1 自启动管理` → `3 开启` / `4 关闭`。

**Q：我重启了好几次，每次自启动都比别人慢几十秒？**  
A：正常。开机链上有两个等待窗口（约 23 秒），是给模块留的安全时间。等它就对了。

**Q：怎么完全恢复到装之前的样子？**  
A：按这个顺序：

1. 每个模块这边 `删除`（Chaos 是 `自启动` → `删除`；想连数据一起删就用 `清除重置`）；
2. 管理器 `2 重建自启动`（把多余的行清掉，确认 `生成 0 行`）；
3. 管理器 `1 自启动管理` → `2 卸载`（**要按两次**，摘掉 flash 开机钩子）；
4. 用系统的方式卸载这两个表盘。

> 注意第 3 步只摘钩子，**不会**删你的 `autorun.json` / `/data/rc` / 模块脚本。

## 11. 名词对照表

| 你在界面上看到的               | 白话            | 实际是什么                            |
| ---------------------- | ------------- | -------------------------------- |
| `rc` / `生成 N 行`        | 开机值班表         | `/data/rc`                       |
| `别人的 M 行`              | 值班表里不属于管理器的部分 | 管理器**一个字都不动**它们                  |
| `总开关` / `自启动闸` / `闸`   | 总电源           | `/data/rc.d/.autorun.on` 这个文件在不在 |
| `init rc` / `开机钩子`     | 总电源接进了配电箱     | flash 里那句 `sh /data/rc &`        |
| `心跳`                   | 上次有没有跑完的记录    | `/data/rc.d/.autorun.log` 的末行    |
| `跑到底`                  | 上次正常跑完了       | 末行是 `cleared`                    |
| `闸被扣住`                 | 上次被打断了        | 末行是 `gate_off`                   |
| `●待重建`                 | 改了但没生效        | 配置和值班表不一致                        |
| `投` / `已投 rc.d/xxx.sh` | 纸条交了          | 模块写好了 `/data/rc.d/<名>.sh`        |
| `重建`                   | 重排值班表         | 重新生成 `/data/rc`                  |
